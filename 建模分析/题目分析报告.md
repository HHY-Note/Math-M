# 通用神经网络处理器下的多核调度问题：题目分析报告

## 1. 分析范围与核心判断

本报告依据用户提供的《2026年中国研究生数学建模竞赛A题（华为）：通用神经网络处理器下的多核调度问题》及同目录附件，完成读题、数据核验、模型选择、数学定义、算法设计与验证计划。**本次仅做建模分析，未实现优化算法、未运行调度性能实验，也不提供虚构的加速比或最优解。** 数据统计来自对全部原始用例的实际只读检查。

建议采用统一的“保无环切图—核心分配—核内子图排序—原评测器反馈”组合优化模型，按三问逐步加入 Task 边界、驻留内存和 FIFO Cache 状态。每问均只采用一个主模型族；下界、基线、消融是验证工具，不另增独立模型。

核心判断：此题优化对象是**固定核内调度器和多核模拟器共同决定的执行时间**。切边数、通信字节数、计算负载均衡和 Cache 命中率都只能解释或筛选候选，不能替代最终 Makespan。子图缩并即使来自原始 DAG，也可能产生有环的商图；商图无环也不保证叠加 Pipe FIFO、内存复用与跨核 COPY 后的执行图无环。

### 4.2 预处理计划

1. 使用原 IO 的重复键检查和原图校验；建立稀疏生产者、消费者、前驱、后继表。不得将 ID 直接当稠密数组下标。
2. 保留原始 COPY 和逻辑张量关系作为证据；优化图中压缩 COPY 路径，只保留非 COPY 操作之间真实可达的依赖。
3. 为每个张量保存生产操作和**全部消费者集合**，作为有向超边；共享张量扇出达 2,666，逐条边相加可能重复估算读取。通信费用按 Task 或核心的消费者去重，并遵守实际构图规则。
4. 预计算拓扑层、计算关键路径、分 Pipe 周期负载、张量复用次数与大小、输入共享集合。不按任意阈值删除大张量或高扇出节点。
5. 按计算节点数、M/V 周期比、共享输入量等特征分层选开发用例；冻结算法后仍报告全部 100 例。训练或调参不使用按 ID 记忆的逐例特例。
6. 预处理均为内存视图，输入附件保持只读。拓扑与扇出边无需展开为消费者两两连接，避免平方级膨胀。

## 5. 共用数学模型与约束

### 5.1 参数与决策

原图为 $G=(V,E)$，操作集 $O$、张量集 $T$，计算决策节点集 $U=O\setminus O_{\mathrm{copy}}$。张量大小 $s_t$，计算周期 $c_o$，给定管道 $p_o$。核心数 $N$，子图数 $K$ 是可变的，$1\leq K\leq |U|$。

决策方案 $\theta=(g,a,\pi)$：$g:U\to\{0,\ldots,K-1\}$ 是满射，$a$ 将子图分配到 $N$ 个核心之一，$\pi_k$ 是核心 $k$ 的子图有序列表。每个计算操作恰属一图，每图恰属一核且在列表中恰出现一次。核心标签和 sgid 只用于表示，规范化可避免等价候选重复评测。

设 $F_q(G,\theta;\eta)$ 表示固定附件评估器在问题 $q$ 和配置 $\eta$ 下的完整输出。运行时间 $C_q(\theta)$、官方新增搬运 $D_q(\theta)$ 均由此提取。采用字典序目标：

$$
\min_{\theta\in\Omega_q}\left(C_q(\theta),D_q(\theta)\right)_{\mathrm{lex}}.
$$

即先选较小 Makespan；相同整数周期时再选较少搬运。题目没有提供两者换算权重，不设置未经依据的加权总分。不可执行方案不进入可行域 $\Omega_q$。有预算的启发式只返回已验证可行的最好候选，不声称全局最优。

### 5.2 固定参数

| 参数 | 数值 | 含义 |
|---|---:|---|
| $M_{\mathrm{L1}}$ | 524,288 bytes | 每核 L1 容量 |
| $M_{\mathrm{UB}}$ | 131,072 bytes | 每核 UB 容量 |
| $B_{\mathrm{D}}$ | 60 bytes/cycle | 全核 DDR 读写合计带宽 |
| $\delta_{\mathrm{A},s}$ | 100 cycles | A 同核前序 Task 等待 |
| $\delta_{\mathrm{A},c}$ | 1,000 cycles | A 跨核前驱 Task 等待 |
| $\delta_{\mathrm{B}}$ | 500 cycles | B 跨核 COPY_OUT 后释放延迟 |
| $M_{\mathrm{C}}$ | 1,048,576 bytes | L2 容量，按配置为 1 MiB |
| $B_{\mathrm{C}}$ | 250 bytes/cycle | Cache 读总带宽，与 DDR 独立 |

题面写 1 MB，计算采用配置中的 1,048,576 bytes，不换成 1,000,000。四条 Pipe 每核各一个执行器；只要依赖允许，不同 Pipe 可以并行。不存在独立的每核 60 bytes/cycle DDR，也不将读和写各自分配 60。

### 5.3 依赖、流水与内存

由计算依赖生成子图商图 $Q(\theta)$，要求无环。问题 1 再叠加同核相邻 Task 顺序边；问题 2/3 需对展开后的操作执行图，加上局部数据边、内存复用边、Pipe FIFO 边和跨核 COPY 边，检查无环。

展开操作 $o$ 的起止时刻记为 $S_o,F_o$。对计算操作 $F_o-S_o=c_o$；对依赖 $(u,v)$，$S_v\geq F_u$，额外释放延迟另按场景加入。对于同核同 Pipe 的既定相邻操作，后者不得早于前者完成；不得由优化器私自重排其 FIFO。

以 $\mathcal{R}_{k,m}(\tau)$ 表示时刻 $\tau$ 核心 $k$、内存类型 $m$ 中的**实际驻留实例**集合，约束为：

$$
\sum_{t\in\mathcal{R}_{k,m}(\tau)}s_t\leq M_m,
\qquad m\in\{\mathrm{L1},\mathrm{UB}\}.
$$

驻留实例需区分 Spill 后的重命名版本；在发射前先申请输出，在最后消费者完成后释放输入，不能在操作开始时提前释放仍被读取的输入。Step2 自动插入 Spill，Step3 补内存复用依赖；候选评分必须包含其开销。静态“子图全部张量总和不超容量”过强且错误，峰值由重叠生命周期决定。

### 5.4 共享带宽与搬运统计

在某带宽池 $P$ 内，若有 $n_P(\tau)>0$ 个活跃搬运，容量为 $B_P$，搬运 $j$ 的剩余字节量 $r_j$ 满足事件间：

$$
\frac{\mathrm{d} r_j}{\mathrm{d}\tau}=-\frac{B_P}{n_P(\tau)}.
$$

加入、完成时先结算旧活跃集合，再更新速率；整数结束周期按原模拟器取整。不能用固定 $s_t/B_{\mathrm{D}}$ 取代并发时长。DDR 与 Cache 分别维护上述方程；片上 COPY 不占 DDR 池，但仍占 Pipe。

官方搬运字段定义为 $D_q=D_{\mathrm{sched},q}-D_{\mathrm{orig}}$，另可拆成切分新增与 Spill 新增。题一、题二该口径对应 DDR COPY；题三必须保留第 2.3 节说明：命中路径属于 Cache，`scheduled_copy_bytes` 仍计入其操作字节数。若研究物理带宽，则按时间线 `memory_path` 对 DDR 操作单独加总，不使用 `cross_task_traffic` 代替全部读写。

### 5.5 假设分级

| 等级 | 假设或采用的规则 | 依据 | 放宽后处理 |
|---|---|---|---|
| 关键 K1 | 操作不可分割、计算周期确定，张量内容不变且依赖真实 | 题面原图和固定评测 | 若允许重算、分块或动态周期，需重新定义输出和目标，不在当前模型内 |
| 关键 K2 | 同构核心、固定四 Pipe 与配置，原评测器作为成绩依据 | 附录 A—D、config | 硬件或版本改变时重跑全部评测 |
| 关键 K3 | 调度只决定切图、分核和子图次序，核内三步与 Cache 策略固定 | 附录 B—D | 可控维度改变后重新建模，不能沿用当前最优性结论 |
| 可放宽 R1 | 快速筛选可用无争用搬运时间 | 只作为候选排序近似 | 用真实并发仿真复评，比较排序错判，不作为结果 |
| 可放宽 R2 | 初始化优先拓扑连续分块 | 便于保无环的算法设计 | 扩展为非连续但商图无环的局部移动，并全局复验 |
| 可放宽 R3 | 多尺度候选和有限搜索预算 | 大图规模与有限运行时间 | 增加预算绘制质量—时间曲线；不外推最优保证 |

算法策略不是硬件事实；不额外假定任意合并有益、Cache 必然加速、加速比不超过核数或不存在带宽瓶颈。

## 6. 问题 1：Task 边界代价驱动的无环切图与调度

### 6.1 建模重点

每个子图就是一个 Task，即使前后 Task 同核，也不能保留片上数据。Tensor 超边的通信费用取决于涉及的 Task 集合，需考虑输入重复搬入、跨 Task 输出和 Spill；不能简单给每条二部边赋相同代价。

对 Task $b$，激活时间 $A_b$ 满足：

$$
A_b\geq\max\left(\{0\}\cup\{F_d:d\in\operatorname{pred}(b),a(d)=a(b)\}\cup
\{F_d+\delta_{\mathrm{A},c}:d\in\operatorname{pred}(b),a(d)\neq a(b)\}\cup
\{F_{\operatorname{prev}(b)}+\delta_{\mathrm{A},s}\}\right).
$$

其中 $F_d$ 为 Task 的结束时刻，与操作结束时刻符号按对象区分；没有同核前序时移除最后一项。100 与 1,000 是并列约束取最大，不是逐个前驱累加。Task 内部起止时间由仿真产生，不把 Task 固定成一个单管道作业。

### 6.2 可实现的搜索步骤

1. 收缩 COPY 路径，建立计算依赖 DAG 和张量超边；选择按后继计算关键路径优先、ID 打破并列的确定性拓扑序。
2. 初始化多个粒度：整图单块、约 $N$、$2N$、$4N$ 个拓扑连续块（超过节点数则截断并去重）。除整图候选外，按累计计算周期而非节点数近似分段。上述倍数是待验证搜索设置，不是题面要求。
3. 对每个候选分区，按商图就绪列表选择关键路径优先的子图，尝试所有核心；用双计算 Pipe 负载、边界字节和等待时间估算最早完成代价，构造初始 $a,\pi$。同一全局拓扑序投影到各核，作为保守起点。
4. 对初始候选调用原评测器，保存最佳可行方案。整图单核候选也需实际校验，不因理论可容纳就略过失败检查。
5. 邻域依次包括：相邻块合并、沿拓扑序拆分、边界操作迁移、子图跨核移动、同核无依赖块交换。每次先检查商图与 Task 顺序图，再用张量去重计数筛选，最后用原评测器评价入围候选。
6. 缓存相同图、配置、分区、顺序的评价；超过预算、完整邻域无改进或达到最大轮次时停止，只输出保存的可行最好方案。失败候选记录原因并丢弃，不返回部分结果。

候选取舍以真实字典序目标为准。快速优先级可用计算关键路径 $h(o)=c_o+\max_{v\in\operatorname{succ}(o)}h(v)$，终端后继项取 0。它只用于排序，不把其他 Pipe 的并行周期重复当成总运行时间。

### 6.3 预期解释与验证

应回答“哪些图适合粗切、哪些适合细切”“收益是否来自并行还是减少 Spill”。拟比较整图单核、按周期拓扑均分、通信聚合与完整方法；题给随机 stub 只用于格式检查，不能作为唯一性能基线。合并减少边界开销但可能损害并行并增大 Spill，故合并收益必须实测，不能假设单调。

## 7. 问题 2：同核复用与内存生命周期联合优化

### 7.1 对问题 1 的变化

每个核心的全部子图合并为一个 Task，同核子图之间不插入边界 COPY；但其次序会影响核内拓扑序、张量存活区间和 Spill。**子图数不再等于 Task 数，减少子图数也不一定减少通信。** 核心依赖图允许出现往返通信，只要实际操作执行图没有等待环，不应误要求“每核一个节点的商图必须无环”。

跨核数据搬运约束为：

$$
S_{\mathrm{in}}\geq F_{\mathrm{out}}+\delta_{\mathrm{B}}.
$$

500 cycles 仅为释放延迟，不占 Pipe 或带宽，不适用于每个同核边。目标 COPY_IN 就绪后仍可能因 Pipe、容量及共享带宽等待。

当前代码按实际源核—目标核组合插入 COPY 对：同一张量从一源核发往多个目标核，可能为每个目标生成一次 COPY_OUT，不能未经核实用“一次写回、多次读取”的广播费用替代。该规则见 `multicore_cut_evaluate_problem_2.py::_build_scene_b_tasks`。

### 7.2 算法增量

先把问题 1 的合法候选在 B 下重新评价，并补充“每个计算操作一个小子图”的可行起点，允许同核 Task 在核内自动融合；这不是将题一时间直接移植到题二。

随后进行三类协调移动：

- 将高字节依赖的生产者与消费者放在同核，减少跨核 COPY 和同步；同时检查此举是否使关键计算 Pipe 过载。
- 将同核无依赖子图顺序调整为更短的张量存活区间。可用 $H(\theta)=\sum_{k,m}\int\sum_{t\in\mathcal{R}_{k,m}(\tau)}s_t\,\mathrm{d}\tau$ 描述内存占用面积（bytes·cycle），但只作诊断，最终比较仍是 Makespan。
- 对因长驻留造成 Spill 的共享张量，尝试把消费块移近生产块，或迁往其他核心。节省局部驻留与增加跨核传输必须一起仿真。

在廉价筛选后调用原 Step1/2/3 和全局执行校验；将报出的环边类型反馈到邻域回退。仅满足操作数据拓扑序还不够，尤其不能把两个核各自等待对方 FIFO 队首的候选当作有效方案。

### 7.3 验证目标

对照问题 1 与问题 2 时分别给出同一方案的场景效果及各自优化后的结果；二者回答的问题不同。分析每核 L1/UB 峰值、驻留时长、Spill 新增字节、M/V 空闲与跨核同步占比。不事先保证 B 的启发式输出一定快于 A；若失败，保留原候选并解释局部调度顺序或资源拥塞。

## 8. 问题 3：FIFO Cache 与两个共享带宽池

### 8.1 状态模型

沿用 B 的分区、核心和释放约束；增加按逻辑张量键维护的 FIFO 序列 $\mathcal{Q}(\tau)$，容量满足 $\sum_{t\in\mathcal{Q}(\tau)}s_t\leq M_{\mathrm{C}}$。COPY_IN 在**实际发射时刻**判断命中，不在方案生成时或进入就绪队列时判断。

- 命中：发射时进入 Cache 读池，不因本次命中刷新 FIFO 排序。
- 未命中：进入 DDR 池，完成后才插入 Cache；若容量不够，连续淘汰队首直到可放入。
- 已有相同键时不重复插入；单个张量超容量则不缓存。
- COPY_OUT 不通过只读 Cache 获得写带宽加速；同一时刻先完成、再插入、再发射的顺序遵循原评测器。

实现边界：题三 `retire()` 对所有记录了缓存键的 COPY_IN 完成都调用 `insert_cache`，包括发射时命中的读。若键仍驻留，插入函数直接返回，FIFO 顺序不变；若该键在这次命中读的在途期间被其他完成事件淘汰，则本次读完成时会将其重新插入队尾，并可能淘汰其他条目。因此，“命中不刷新”只指命中查询及键仍驻留的情况，不能解释为命中读完成绝不重新插入。FIFO 状态模拟必须复现这一代码规则。

多个核心同时读取尚未入 Cache 的相同数据，可能全部冷失效，不能假设自动合并在途请求。逻辑键必须从评测器实际展开图读取；尤其 Spill 重命名后不能仅凭物理 ID 相似就认定能命中。

命中字节率为：

$$
\rho=\frac{D_{\mathrm{hit}}}{D_{\mathrm{hit}}+D_{\mathrm{miss}}},
$$

分母为 0 时按评测器约定记为 0。不要与“命中次数/访问次数”混用。按代码 `cache_eligible`，资格判断为 COPY_IN，不能自行缩小为只有原始 DDR 输入；跨核读与 Spill 读的实际资格、大小和键由构图与实现决定。

### 8.2 面向 Cache 的搜索

以问题 2 的最佳候选初始化，在可选就绪子图之间优先尝试消费已缓存或即将完成首次载入的共享张量，再用真实评测筛选。不能直接给输出格式添加“等待若干周期”字段；时间对齐只能通过合法的分区、分核与子图排序间接实现。

候选排序可使用潜在读取节约 $s_t(1/B_{\mathrm{D}}-1/B_{\mathrm{C}})$（cycles），但这忽略并发、首次载入完成时刻和 FIFO 驱逐，故仅作筛选特征。原模拟器评价中的收益才可写成实验结论。

FIFO 中“下一次访问前插入多少新字节”可作粗略风险指标，但精确命中还依赖当前队列中旧条目的排列与容量；不能将 LRU 的重用距离判据直接套到 FIFO。高命中率也可能伴随更差的关键路径、Pipe 阻塞或 Cache 读池拥塞。

### 8.3 必须分开的两类对照

1. **固定方案硬件对照**：同一 $\theta$ 在问题 2 和问题 3 评测器运行，以 $C_2(\theta)/C_3(\theta)$ 衡量加入 Cache 的净影响。
2. **分别优化的整体对照**：以各自预算相同的最好方案 $\theta_2,\theta_3$ 比较 $C_2(\theta_2)/C_3(\theta_3)$，同时包含策略变化。

正文报告不能混合两类定义。即使 $N=1$ 也要实际评价题三的有无 L2 比值，不强行设为 1；Spill 可能产生复读。正式结果始终使用固定 1,048,576 bytes、250 bytes/cycle。若以后做容量/带宽敏感性，只能在单独标明的扩展实验中采用复制配置，不能替代固定配置成绩，也不改原 config。

## 9. 指标、下界和验证合同

### 9.1 全量指标

设用例 $i$ 的整图单核基准为 $C_{\mathrm{single},i}$，通过 `singlecore_evaluate.py` 获取。问题 1/2 的逐例加速比及平均曲线定义为：

$$
S_{q,i}(N)=\frac{C_{\mathrm{single},i}}{C_{q,i}(N)},\qquad
\overline{S}_q(N)=\frac{1}{100}\sum_{i=1}^{100}S_{q,i}(N),\quad q\in\{1,2\}.
$$

按题面约定，这两问图中的单核基准点为 1。100 个比值的算术平均与“单核总时间/多核总时间”不同，后者只能另列为总体吞吐诊断。不得删除慢例或失败例来提高平均值；出现失败先修复或明确记为未完成，不能以 0 时间替代。

题三每例同核数加速比为 $R_i(N)=C_{2,i}(N)/C_{3,i}(N)$，其平均仍采用逐例算术平均。无 L2 的 Cache 命中率表项写“不适用”，不能冒称实际测得 0。

逐例结果表未来至少保留：用例、核数、场景、方案指纹、评测配置指纹、Makespan、官方总/原始/新增 COPY 字节、切分与 Spill 拆分、物理 DDR 字节（若统计）、命中字节率、算法生成耗时、可行状态。生成耗时与模拟 Makespan 单位不同，不能混合。

### 9.2 可计算下界与适用范围

设 $W_{\mathrm{M}}$、$W_{\mathrm{V}}$ 为原计算节点在两条计算 Pipe 上的总周期；$L_{\mathrm{comp}}$ 为原计算依赖中仅累加计算周期的最长路径，则所有方案有：

$$
C_q(\theta)\geq\max\left\{L_{\mathrm{comp}},\frac{W_{\mathrm{M}}}{N},\frac{W_{\mathrm{V}}}{N}\right\}.
$$

对固定候选，还可使用其实际 DDR 字节量除以 60 的资源下界；题三另有实际 Cache 读字节量除以 250 的下界。这里的候选实际流量随切图、Spill、命中而变，不能将一个方案的流量下界误当全局最优值的下界。仅凭原图所有 COPY 的 cycles 求和无效，因为输入中这些字段全部为 0。

### 9.3 边界验证与消融

| 验证 | 目的与通过条件 |
|---|---|
| 单链、并行枝、菱形依赖 | 不违反先后关系；粗分区不产生商图环 |
| 单张量多消费者 | 同 Task/核心复用去重与原构图一致，读写分开计数 |
| 一源多目标核 | 核对当前代码按源—目标 COPY 对重复写出的口径 |
| 缓存恰满、输入输出同时驻留 | 发射前瞬时容量不超限；Spill 后引用完整 |
| 全局等待环 | 即使各核局部 DAG 合法，也能拒绝 FIFO/跨核组合环 |
| 两个等大 DDR 搬运并发 | 总带宽为 60，而非每个都为 60 |
| 首次读未完成时第二次读 | 允许同时失效，不凭将来入 Cache 提前判命中 |
| FIFO 命中、重复键与淘汰 | 命中查询不刷新；键仍驻留时完成不重复插入，在途被淘汰则完成后重新插入 |
| 空核、零周期 COPY、小图 | 空核合法；COPY 按字节有耗时；无虚构免费数据流 |
| 去掉通信聚合/内存项/Cache 感知 | 在相同预算下评估各改进的独立贡献 |

以上是后续编程应执行的验证计划，本次未运行这些调度实验。可行性为硬约束，违规数必须为 0，不设百分比容忍；速度收益不预设阈值，报告真实均值、中位数、最差例和完整分布。
